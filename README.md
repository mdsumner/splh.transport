# splh.transport

A cached, single-file copy of the [LIST](https://www.thelist.tas.gov.au/) transport segments
for all 29 Tasmanian municipalities, as GeoParquet (ZSTD), with a `municipality` column added.

Download: <https://github.com/mdsumner/splh.transport/releases/download/latest/LIST_TRANSPORT_SEGMENTS.parquet>

```
gdal vector info /vsicurl/https://github.com/mdsumner/splh.transport/releases/download/latest/LIST_TRANSPORT_SEGMENTS.parquet
```

## Three ways to the same layer

This repo does one job (keep a fast statewide cache), but the same layer can be had
without any of this machinery. All three give the same 286,157 segments with a `municipality` column.

| | what | needs |
|---|---|---|
| **cache** | `LIST_TRANSPORT_SEGMENTS.parquet` on the [`latest` release](https://github.com/mdsumner/splh.transport/releases/tag/latest) | anything that reads GeoParquet; fastest |
| **VRT** | [`recipes/LIST_TRANSPORT_SEGMENTS.vrt`](recipes/LIST_TRANSPORT_SEGMENTS.vrt), an OGR union layer over the 29 remote zips | any GDAL of the last decade |
| **GDALG** | [`recipes/LIST_TRANSPORT_SEGMENTS.gdalg.json`](recipes/LIST_TRANSPORT_SEGMENTS.gdalg.json), a saved `gdal vector pipeline` (concat ! sql ! select) | GDAL >= 3.11 (written with 3.13) |

The recipes are small text files that point straight at
`https://listdata.thelist.tas.gov.au/opendata/data/LIST_TRANSPORT_SEGMENTS_<MUNICIPALITY>.zip`
via `/vsizip//vsicurl/`, so nothing is downloaded up front and they always reflect upstream.
Reading the whole state this way streams ~29 FileGDBs over HTTP (tens of seconds to minutes),
which is the cost the cache avoids. Open them from a clone, or straight from GitHub:

```sh
R=https://raw.githubusercontent.com/mdsumner/splh.transport/main/recipes

gdal vector info /vsicurl/$R/LIST_TRANSPORT_SEGMENTS.vrt
# subset on the fly, write whatever you like
gdal vector filter --where "municipality = 'HOBART'" /vsicurl/$R/LIST_TRANSPORT_SEGMENTS.vrt hobart.gpkg
# or materialise the pipeline (this is the cache, in one line)
gdal vector convert /vsicurl/$R/LIST_TRANSPORT_SEGMENTS.gdalg.json statewide.parquet
```

```r
# R: terra / sf / gdalraster all take the same DSN string
r <- "/vsicurl/https://raw.githubusercontent.com/mdsumner/splh.transport/main/recipes"
x <- terra::vect(file.path(r, "LIST_TRANSPORT_SEGMENTS.vrt"), query = "SELECT * FROM LIST_TRANSPORT_SEGMENTS WHERE municipality = 'FLINDERS'")
```

```python
# Python: pyogrio / geopandas
import geopandas as gpd
r = "/vsicurl/https://raw.githubusercontent.com/mdsumner/splh.transport/main/recipes"
x = gpd.read_file(f"{r}/LIST_TRANSPORT_SEGMENTS.vrt", where="municipality = 'FLINDERS'")
```

In QGIS, *Layer > Add Layer > Add Vector Layer*, protocol HTTP, and paste a raw URL
(or open a downloaded `.vrt` / `.gdalg.json` file directly; GDALG needs QGIS built on GDAL >= 3.11).

The recipes are regenerated by `scripts/recipes.sh` from `scripts/municipalities.txt`;
the weekly workflow checks the VRT still resolves against upstream.

## How it updates

`.github/workflows/refresh.yml` runs weekly (and on demand via *Run workflow*):

1. `scripts/probe.sh` HEADs every upstream zip and records `Last-Modified`, `ETag` and size in `manifest.tsv`.
2. If that differs from the `manifest.tsv` on the `latest` release (or *force* is ticked),
   `scripts/build.sh` rebuilds the parquet inside a pinned GDAL container.
3. The parquet and the new manifest are uploaded to the `latest` release.

The `manifest.tsv` release asset records the upstream state the current parquet was built from.

Run locally (GDAL >= 3.11 with Parquet):

```
scripts/build.sh work LIST_TRANSPORT_SEGMENTS.parquet
```
